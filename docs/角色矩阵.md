# ORIN 角色矩阵

本文档定义当前首版权限口径。现阶段先收敛为两类角色：管理员与普通用户；后续再把具体资源权限拆成可赋予用户的细粒度能力。

## 1. 角色定义

| 角色 | 定位 | 默认入口 | 可见模块 |
|------|------|----------|----------|
| `ROLE_ADMIN` | 管理员 | `/workspace/overview` | 产品主线：概览、Agent、运行、发布、资源、系统设置 |
| `ROLE_USER` | 普通用户 / API 调用方 | `/portal/api-keys` | API 中转站：个人 `CLIENT_ACCESS` Key 创建、轮换、禁用与调用历史 |

兼容口径：前端仍识别历史 `ADMIN` / `USER` 字符串；后端权限判断以 `ROLE_*` 为准。

## 2. 前端权限口径

- 菜单来源统一为 `orin-frontend/src/router/topMenuConfig.js`。
- 管理员看到“概览、Agent、运行、发布、资源、系统设置”六个主入口；系统设置内只主动暴露治理概览、用户管理和审计记录，环境参数与日志策略通过高级运维下钻；历史页面保留路由，但不再全部主动暴露。
- 普通用户不进入 dashboard 模块，访问 `/dashboard` 或 dashboard 子页面时回到 `/portal/api-keys`。
- 普通用户访问 `/workspace/**` 时同样回到 `/portal/api-keys`。
- `/dashboard` 根路径按角色默认入口跳转；用户显式访问有权限的具体页面时不再被默认首页覆盖。

## 3. 后端权限口径

- 当前前端只暴露 `ROLE_ADMIN` 与 `ROLE_USER` 两类角色。
- `/api/v1/users/**`、`/api/v1/departments/**`、`/api/v1/roles/**` 属于管理员能力。
- `/api/v1/api-keys/**` 分为两类：`ROLE_ADMIN` 可做全局治理；`ROLE_USER` 只能管理自己拥有的 `CLIENT_ACCESS` Key。
- 普通用户 API Key 所有权只来自 JWT 当前用户，不能通过 `X-User-Id` 或 `targetUserId` 覆盖；访问他人 Key 按不可见处理。
- API Key 明文回显、配额重置、`PROVIDER_CREDENTIAL` 与 `MCP_ENV` 密钥管理仍仅限管理员。
- `/api/v1/runs/**` 是资源级 ACL：普通用户只可读取、取消和重试自己的 Run；`ROLE_OPERATOR` 与 `ROLE_ADMIN` 可处理任意 Run；旧记录没有可解析的 owner 时只向特权角色开放。
- `/v1/**` API Key 通道与 `/api/v1/**` JWT 业务通道继续隔离。

## 4. 后续边界

- 细粒度权限后续按“权限赋予用户”的方式做，不再先扩展一批固定角色。
- 后续权限拆分优先围绕资源访问、API Key 能力、模型 / 知识库 / 工作流管理边界展开。
