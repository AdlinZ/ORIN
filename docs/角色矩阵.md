# ORIN 角色矩阵

本文档定义产品人物、管理台首版角色化体验与后端权限收口口径。当前只使用已有数据库角色，不因产品命名新增角色枚举。

## 1. 核心产品人物

ORIN 的核心使用人物是**企业 AI 应用管理员**：负责集中建设、验证、发布和治理知识型智能体的人。他通常来自数字化、信息化、AI 产品或数据团队，主要完成以下工作：

1. 接入并维护模型 Provider。
2. 创建知识库，处理文档解析、向量化与检索质量。
3. 创建智能体并绑定知识库。
4. 调试回答、引用、Token、耗时、错误和 Trace。
5. 管理发布入口、API Key、权限与审计。

首版不新增 `ROLE_AI_ADMIN`。该人物的日常资产操作由现有 `ROLE_OPERATOR` 承载，平台级密钥、组织权限和全局配置仍由管理员角色负责。

次级人物：

| 人物 | 主要目标 | 当前角色映射 |
|------|----------|--------------|
| 知识运营人员 | 维护资料、处理失败文档、验证检索质量 | 暂由 `ROLE_OPERATOR` 承载；资源级权限待补 |
| AI 应用开发者 | 通过 API/MCP 接入已发布智能体并排查 Trace | `ROLE_OPERATOR` 或 `ROLE_USER` + 个人 API Key |
| 平台管理员 | 管理组织、Provider 密钥、安全策略和系统健康 | `ROLE_PLATFORM_ADMIN` / `ROLE_ADMIN` / `ROLE_SUPER_ADMIN` |
| 业务使用者 | 使用已发布智能体并提交反馈 | `ROLE_USER` |

## 2. 系统角色定义

| 角色 | 定位 | 默认入口 | 管理台可见模块 |
|------|------|----------|----------------|
| `ROLE_SUPER_ADMIN` | 超级管理员 | `/dashboard/runtime/overview` | 全部管理模块 |
| `ROLE_PLATFORM_ADMIN` | 平台管理员 | `/dashboard/runtime/overview` | 运行监控、系统设置；组织权限默认不开启 |
| `ROLE_ADMIN` | 系统管理员 | `/dashboard/runtime/overview` | 全部管理模块 |
| `ROLE_OPERATOR` | AI 应用管理员 / 知识运营人员 | `/dashboard/applications/home` | 智能体、知识库；工作流和 MCP 等高级能力按现有权限开放 |
| `ROLE_USER` | 普通使用者 | `/portal` | 不进入管理台模块；可进入 `/portal/api-keys` 管理个人访问密钥 |

兼容口径：前端仍识别历史 `ADMIN` / `USER` 字符串；后端权限判断以 `ROLE_*` 为准。

## 3. 前端权限口径

- 菜单来源统一为 `orin-frontend/src/router/topMenuConfig.js`。
- 顶部菜单和侧边栏使用同一套 `roles` 声明过滤一级菜单与子菜单。
- 路由守卫同时检查父级模块和子页面 `meta.roles`，直接输入 URL 也必须满足角色要求。
- `/dashboard` 和监控总览会按角色默认入口跳转，避免普通用户或运维落到管理员视图。

## 4. 后端权限口径

- `/api/v1/users/**`、`/api/v1/departments/**`、`/api/v1/roles/**` 不再匿名放行。
- 用户、部门、角色管理控制器要求 `ROLE_ADMIN` 或 `ROLE_SUPER_ADMIN`；`ROLE_PLATFORM_ADMIN` 默认不具备组织权限。
- `/api/v1/users/profile/**`、`/api/v1/users/dashboard/**`、`/api/v1/users/avatar` 属于个人资料能力，仍走 JWT 认证，不作为管理员管理接口。
- `/api/v1/api-keys/**` 分为两类权限：`ROLE_ADMIN`、`ROLE_SUPER_ADMIN`、`ROLE_PLATFORM_ADMIN` 可做全局治理；`ROLE_OPERATOR`、`ROLE_USER` 只能创建、列表、启用、禁用、删除、轮换和查看自己拥有的 `CLIENT_ACCESS` Key 使用历史。
- 普通角色的 API Key 所有权只来自 JWT 当前用户，不能通过 `X-User-Id` 或 `targetUserId` 覆盖；访问他人 Key 按不可见处理，返回 `404`。
- API Key 明文回显、配额重置、`PROVIDER_CREDENTIAL` 与 `MCP_ENV` 密钥管理仍仅限管理员 / 平台管理员角色。
- `/v1/**` API Key 通道与 `/api/v1/**` JWT 业务通道继续隔离。

## 5. 归属 / 状态 / 审计语义（对齐口径）

在资源级 ACL 落地前，先统一字段语义，避免前后端各说各话：

| 对象 | 归属 | 业务/发布状态 | 运行或处理状态 | 审计 |
|------|------|---------------|----------------|------|
| 智能体 | `agent_metadata.owner_user_id` | 发布口径 = `mcpExposed` | 运行态在 `AgentHealthStatus.status`：`RUNNING / STOPPED / HIGH_LOAD / ERROR / UNKNOWN` | 对话写 `AGENT_CHAT`；切换 `mcpExposed` 写 `AGENT_MCP_EXPOSED` |
| 知识库 | `knowledge_bases.owner_user_id`（创建/同步时盖章） | `ENABLED / DISABLED` | 文档 `parseStatus` × `vectorStatus`（含脱敏 `vectorError`） | 创建/更新/删除/上传/解析/向量化/检索审计写入当前用户，不再固定 `SYSTEM` |
| 工作流 | `owner_user_id` + `mcpExposed` | 与智能体发布语义一致 | 任务状态走统一 Task 枚举 | 既有 Workflow / MCP 审计 |

说明：

- 当前列表接口仍返回平台可见资产；`owner_user_id` 用于展示、审计与后续 ACL，不代表本阶段已按归属过滤。
- 智能体调试入口统一称“工作台”；列表/控制台深链进入同一 `AgentWorkspace`，控制台是锁定单个智能体的别名。
- 知识库主导航收敛为“知识资产 + 知识检索”；旧 `center` 路径继续重定向到检索实验室。

## 6. 后续边界

- 本阶段不新增审计员角色、不做租户隔离、不做资源级 ACL。
- 按 key 长期配额趋势、细粒度模型 / 知识库权限放入后续 Phase 2。
- “企业 AI 应用管理员”是产品人物，不等同于新的数据库角色；在资源级 ACL 完成前，不扩大 `ROLE_OPERATOR` 的后端权限。
