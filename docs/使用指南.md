面向使用者：从哪里进入功能、联调时先看什么、如何快速验证。

## 2. 主导航

前端按当前 `orin-frontend/src/router/topMenuConfig.js` 组织菜单，并按角色过滤一级菜单和子菜单。主导航围绕一条产品闭环组织：

```text
构建 Agent / Workflow → 连接 MCP / 知识 → 运行验证 → 发布 Endpoint → Trace / 审计治理
```

管理员主导航只保留 6 个一级入口。其中概览、运行、发布只有一个明确目的地，点击后直接进入页面，不再显示只有一个选项的下拉菜单；Agent、资源、系统设置保留真正需要选择的二级入口：

| 分组 | 主路径 | 菜单入口 | 产品含义 |
|------|--------|----------|----------|
| 概览 | `/workspace/overview` | 产品概览 | 查看唯一下一步、就绪证据和最近交付 |
| Agent | `/workspace/agents` | Agent 列表、工作流 | 定义并冻结可执行能力 |
| 运行 | `/workspace/runs` | 运行中心 | 发起、跟进、看结果和处理失败 |
| 发布 | `/workspace/endpoints` | 发布中心 | 将能力交付给 REST / MCP 客户端 |
| 资源 | `/workspace/runners` | Runner、模型、知识库、MCP 工具 | 管理 Agent 依赖的执行和上下文资源 |
| 系统设置 | `/dashboard/control/admin-overview` | 系统概览、用户管理、审计记录 | 先判断治理异常，再进入日常管理；环境与日志策略只作为高级运维下钻 |

未列入主导航的历史页面没有删除，仍可通过现有 URL 和历史重定向访问，但不再作为产品主入口。新增功能默认不得增加一级菜单；只有进入上述闭环且具备验收证据时，才考虑加入对应分组。

产品概览不再展示通用统计仪表盘。首页只给出一个当前行动，并用 Agent、冻结版本、Runner、Run 结果和对外服务五项事实解释判断；最近一次 Run 与当前服务作为闭环证据保留。若最近 Run 失败，它会优先于旧的成功记录成为下一步；从当前服务可直接打开对应发布项的调用说明。

产品概览同时提供“首次交付向导”，把内部概念翻译为五个用户动作：创建 Agent、固定可运行版本、接入执行节点、验证一次输出、发布给用户。向导直接复用上述五项真实状态自动计算进度，不建立第二套完成标记；每一步都可以点击进入对应页面，也可以收起后继续只看当前唯一行动。

系统设置默认进入治理概览，不再直接打开环境参数控制台。主导航只保留系统概览、用户管理和审计记录；审计记录默认只读，环境参数、审计保留策略和 Logger 调试需要从“高级运维”显式进入。

## 2.1 角色入口

| 角色 | 默认入口 | 说明 |
|------|----------|------|
| `ROLE_ADMIN` | `/workspace/overview` | 可见概览、Agent、运行、发布、资源、系统设置六个入口 |
| `ROLE_USER` | `/portal/api-keys` | 只使用个人 API Key 门户，不进入管理台 |

角色边界详见 [角色矩阵.md](./角色矩阵.md)。直接输入不可见模块 URL 时，路由守卫会按同一角色矩阵拦截。

## 3. 常用功能入口

### 3.1 构建

| 要做的事 | 从哪里进入 |
|----------|------------|
| 创建 Agent、继续配置草稿、冻结版本 | `/workspace/agents` |
| 从“可运行”Agent 直接进入运行或发布 | `/workspace/agents` 的“下一步”列 |
| 管理和编排 Workflow | `/dashboard/applications/workflows` |
| 管理 Agent 可用的 MCP 工具服务 | `/dashboard/applications/mcp-tools` |
| 管理 Agent / Workflow 使用的知识 | `/dashboard/resources/center` |

工作流入口按“可运行 / 待发布 / 需修复 / 已归档”展示交付状态。只有已经发布且当前编排校验通过的工作流才标记为“可运行”；草稿校验通过后可直接“发布并验证”，历史发布状态但当前编排无效的工作流会明确要求先修复。日常列表不展示节点数、DSL 版本和来源筛选，只保留创建、修复、发布和运行验证；执行历史从具体工作流进入，Dify 导入导出、详细校验、归档和删除等低频操作保留在 `/dashboard/applications/workflows/advanced`。

知识库入口只汇总“已有内容 / 待添加内容 / 已停用”三种决策状态，不再用知识库总数和文档总数占用首屏。推荐顺序是：创建知识库 → 进入详情上传或管理文档 → 从列表点击“测试并用于 Agent”进入检索验证 → 选择 Agent 应用验证通过的知识。`/dashboard/resources/assets` 是知识图谱等高级资产视图，只从列表底部进入，不作为页头日常操作。

MCP 工具入口按“可用于 Agent / 待验证 / 故障或停用”汇总服务。只有已启用并通过 MCP `tools/list` 验证的服务才表达为可用；命令和 URL 不在主列表展开，模板安装、密钥引用和删除等低频操作保留在 `/dashboard/applications/extensions?tab=mcp` 高级管理页。

Agent 列表只展示名称、说明、模型、交付状态和下一步动作，不在主表重复展示供应商与版本号。点击整行进入草稿或版本历史；可运行 Agent 的常驻动作只有运行和发布。Agent 草稿默认只展示名称、说明、系统指令和模型，运行模式、采样参数与凭据绑定属于高级配置，按需展开。

冻结后的版本详情以“可运行能力”展示版本状态、说明和凭据依赖，并可直接进入运行或发布；版本 ID、内容摘要和快照格式只在技术信息中按需展开。

版本历史以“当前使用 / 可运行 / 已退役”表达交付状态，不再把 digest 作为主列表信息。从任一冻结版本进入运行或发布时，系统会保留该版本选择；管理员和 Operator 可在“版本管理”中变更默认版本或退役历史版本。

### 3.2 运行

| 要做的事 | 从哪里进入 |
|----------|------------|
| 开始运行并查看结果 | `/workspace/runs` |
| 接入和管理 Runner | `/workspace/runners` |
| 从运行详情查看日志、事件和分配记录 | `/workspace/runs/:runId` |
| 需要深入排障时从运行详情的“技术信息”进入 Trace | `/workspace/runs/:runId` |

运行中心按“进行中 / 已产出结果 / 需要处理 / 已停止”组织记录，概览只保留前三种需要日常判断的结果，不再用总记录数占用首屏。主列表只展示任务、结果状态、Agent、最近变化和下一步，不暴露版本号、Runner 与运行编号等调度字段。失败任务可以直接进入原因诊断或重新运行；Trace 不再作为主菜单入口，只从具体运行的技术信息中下钻，避免脱离业务结果浏览底层调用链。

运行详情先展示输入、输出或失败原因；事件、日志、调度记录、标识和 Trace 统一收在可展开的诊断区。

开始运行时只需选择 Agent、再描述任务，任务内容不能为空。系统默认选中当前冻结版本和可用 Runner；如需覆盖默认选择，可展开“高级运行设置”。创建成功后直接进入运行结果页。

Runner 页面以“是否可以执行任务”为主：顶部先显示可运行、需要处理和暂停接单的节点数，列表只展示任务负载、最近连接和下一步动作；CPU、内存等硬件信息进入 Runner 详情查看。`ONLINE / DRAINING / DEGRADED` 等内部状态在界面中统一表达为“可运行 / 暂停接单 / 需要检查”。

Runner 详情先回答节点能否接收任务，并展示最近连接、负载、运行环境和资源使用。离线节点会直接给出恢复方式；Runner ID、凭据摘要和心跳明细统一收在“诊断与接入信息”中。暂停接单只停止领取新任务，不中断正在执行的任务；“永久撤销接入”会使凭据失效且不可恢复。

接入 Runner 按三步完成：

1. 创建一次性接入凭据，并为节点设置容易识别的名称。
2. 选择 Python 或 Docker，只复制并执行对应方式的命令。
3. 页面自动检查 Runner 是否上线；确认“可以运行”后再返回运行创建页。

从“运行中心”或“产品概览”的无 Runner 阻塞提示进入时，接入成功会保留上下文并返回“开始运行”。关闭命令窗口不等于接入完成，必须以第三步检测到 Runner 上线为准。

### 3.3 发布

| 要做的事 | 从哪里进入 |
|----------|------------|
| 将已验证 Agent 发布为 REST / MCP 服务 | `/workspace/endpoints` |
| 重新查看服务调用方式 | `/workspace/endpoints` 的“查看调用方式” |

发布成功后先保存一次性 API Key。确认安全保存后，页面只展示发布时选择的协议：REST 服务提供调用地址与 curl，MCP 服务提供客户端配置，不再混合展示另一种交付方式。

发布窗口按“选择 Agent → 选择调用方式 → 设置服务信息”组织；默认使用当前冻结版本，多版本场景可在发布设置中切换。REST API 面向应用和脚本，MCP 工具面向支持 MCP 的 AI 客户端。

历史服务可以随时重新打开调用说明；示例中的 `YOUR_API_KEY` 需要替换为发布时安全保存的专属密钥。统一网关、密钥轮换和配额属于高级管理能力，从调用说明中的“高级密钥管理”进入，不再占用发布主菜单。

### 3.4 管理

| 要做的事 | 从哪里进入 |
|----------|------------|
| 管理模型 | `/dashboard/applications/models` |
| 管理用户 | `/dashboard/control/users` |
| 判断系统治理状态 | `/dashboard/control/admin-overview` |
| 查看审计记录 | `/dashboard/control/audit-logs` |
| 高级：管理环境参数 | 系统设置 → 高级运维 → 环境参数 |
| 高级：调整审计策略 / Logger | 系统设置 → 高级运维 → 审计策略 |

模型入口默认只回答三个问题：哪些模型可用于 Agent、哪些模型缺少供应商凭据、哪些模型已停用。列表每页展示 20 个模型；创建时间、批量删除、定价和批量导入等低频信息移到 `/dashboard/applications/models/advanced`。从“管理供应商凭据”会直接进入统一网关的供应商凭据标签。

## 4. 第一次使用：最小验证流程

```bash
# 1. 启动三端
./manage.sh start

# 2. 烟测
bash scripts/smoke-test.sh

# 3. 浏览器访问
open http://localhost:5173
```

最小可验证清单：

- [ ] `/`、`/portal` 可打开，无白屏
- [ ] 登录成功（默认账号由本地配置或初始化向导创建；生产环境不得使用示例密码）
- [ ] `/workspace/agents` 可打开，Agent 构建入口可见
- [ ] `/workspace/overview` 可打开，只显示一个当前行动，并可看到五项就绪证据、最近 Run 与当前服务
- [ ] `/workspace/runs` 可打开，运行入口可见
- [ ] `/workspace/endpoints` 可打开，发布入口可见
- [ ] Agent / Run / Endpoint 主列表默认显示名称、状态和下一步动作，不以长 ID 作为主要信息
- [ ] 没有在线 Runner 时，概览和运行页都明确提示阻塞，并引导到 Runner 接入
- [ ] Runner 接入按“创建凭据 → 启动 Runner → 确认上线”完成，并能返回运行创建页
- [ ] `/dashboard/applications/workflows` 可打开，工作流页面无白屏
- [ ] `/dashboard/control/gateway` 高级管理页仍可打开，但不占用发布主菜单

## 5. 联调要点

### 5.1 看接口是否真存在

```bash
# 直接搜后端控制器
rg "@RequestMapping|@GetMapping|@PostMapping" \
   orin-backend/src/main/java/com/adlin/orin

# 或打开 Swagger
open http://localhost:8080/swagger-ui/index.html
```

### 5.2 看页面入口是否还在用

```bash
# 路由常量
sed -n '1,260p' orin-frontend/src/router/routes.js

# 顶部菜单可见性（角色过滤与开关）
sed -n '1,260p' orin-frontend/src/router/topMenuConfig.js

# 找开发中提示或未启用提示
rg "开发中|未启用|待实现" orin-frontend/src
```

### 5.3 看工作流/协作是否真执行

涉及工作流、协作、知识链路时，必须同时核对三层：

1. 前端节点配置和入口页
2. Java 后端控制器与代理层
3. Python `orin-ai-engine/app/engine` 节点处理器与 TaskRuntime

页面可点开 ≠ 能力闭环。

## 6. 文档使用原则

- 路由常量、菜单项、组件文件三者都存在，仍不等于能力闭环
- 部分路径（版本管理、协作配置等）是同页面别名复用
- 模块成熟度请对照 [功能完成度.md](./功能完成度.md)
- 接口字段以 Swagger 与控制器代码为准

## 7. 历史路径与重定向

以下路径来自 `LEGACY_ROUTE_REDIRECTS` 或旧文档，仅用于兼容访问和排查历史链接，不作为当前主导航入口：

| 旧路径示例 | 当前处理口径 |
|------------|--------------|
| `/dashboard/agents/list`、`/dashboard/agents/onboard`、`/dashboard/agents/chat-logs` | 保留到旧智能体页面的兼容重定向；新的 Agent 主入口是 `/workspace/agents` |
| `/dashboard/applications/*` | Workflow、MCP、模型等仍在使用的落地页，以及旧智能体相关页面；菜单入口以本指南第 2 节为准 |
| `/dashboard/knowledge/*` | 历史知识库路径；当前从 `/dashboard/resources/center` 或 `/dashboard/resources/assets` 进入 |
| `/dashboard/resources/*` | 当前知识资源落地页；`center` 是知识库清单，`retrieval` 是检索验证，`assets` 是高级资产视图 |
| `/dashboard/runtime/*` | 运行观测落地页；主导航只主动暴露运行中心，Trace 与告警按运行证据下钻 |
| `/dashboard/control/*` | 系统管理落地页；主导航只主动暴露系统概览、用户管理和审计记录，环境与日志策略属于高级运维 |
| `/dashboard/system/users`、`/dashboard/system/api-keys`、`/dashboard/system/audit-logs` | 旧系统管理路径；分别进入 `/dashboard/control/users`、`/dashboard/control/gateway`、`/dashboard/control/audit-logs` 等当前落地页 |
