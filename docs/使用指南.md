# ORIN 使用指南

面向企业 AI 应用管理员：如何建设知识库、创建智能体、验证效果并完成发布治理。路由清单用于定位当前实现，不代表产品优先级。

## 0. 你是谁，以及先完成什么

本指南的核心读者是负责建设和治理企业知识型智能体的 AI 应用管理员。第一次使用 ORIN 时，优先完成两条闭环：

### 0.1 知识库闭环

```text
创建知识库
→ 上传文档
→ 查看解析与向量化状态
→ 运行检索测试
→ 确认结果与失败原因
```

### 0.2 智能体闭环

```text
接入可用模型
→ 创建智能体
→ 绑定已验证知识库
→ 调试回答与引用
→ 查看 Token、耗时、Trace 和审计
→ 通过门户、API 或 MCP 交付
```

Workflow、MCP、多智能体协作、知识图谱和多模态是高级能力。只有核心闭环需要它们时再启用，不作为首次上手的前置步骤。

## 2. 主导航

前端按当前 `orin-frontend/src/router/topMenuConfig.js` 组织顶部菜单与侧边栏，并按角色过滤一级菜单和子菜单。判断“主入口”时，以角色可见菜单为准；`ROUTES` 常量里的落地页路径和历史重定向路径不能单独当作菜单入口。

从产品任务理解当前入口时，按以下层级使用：

| 层级 | 能力 |
|------|------|
| 核心资产 | 智能体、知识库、模型 Provider |
| 验证与交付 | 运维工作台、调试工作台、知识检索、API Key、Trace、审计 |
| 高级能力 | Workflow、MCP、多智能体协作、知识图谱、多模态 |
| 平台治理 | 用户、角色、系统配置、监控与维护 |

当前一级菜单按产品优先级排列：

| 一级菜单 | 主要入口 | 产品口径 |
|----------|----------|----------|
| 智能体 | 运维工作台、智能体列表、会话记录 | 核心资产、日常运营与调试入口；调试工作台从列表/运维页进入 |
| 知识库 | 知识资产、知识检索 | 核心知识建设与验证入口 |
| 高级能力 | 工作流、可视化编排、执行记录、多智能体协作、扩展与 MCP | 核心闭环需要时再使用 |
| 运行监控 | 监控、Trace、用量、性能、告警与日志 | 管理员运行治理入口 |
| 组织权限 | 用户、部门、角色 | 超级管理员组织治理入口 |
| 系统设置 | 模型、定价、环境、通知、数据资产、MCP、网关 | 管理员平台配置入口 |

`ROLE_OPERATOR` 默认只看到“智能体 → 知识库 → 高级能力”；管理员再按权限看到运行监控、组织权限和系统设置。菜单由 `topMenuConfig.js` 统一过滤，`routes.js` 中的 `SIDEBAR_MENU_CONFIG` 只服务旧面包屑兼容，不作为当前导航真相。

## 2.1 角色入口

| 角色 | 默认入口 | 说明 |
|------|----------|------|
| `ROLE_SUPER_ADMIN` / `ROLE_ADMIN` | `/dashboard/runtime/overview` | 可见管理台完整入口 |
| `ROLE_PLATFORM_ADMIN` | `/dashboard/runtime/overview` | 可见运行监控与系统设置；组织权限默认不开启 |
| `ROLE_OPERATOR` | `/dashboard/applications/home` | AI 应用管理员落地运维工作台，可见智能体、知识库及现有高级能力入口 |
| `ROLE_USER` | `/portal` | 使用服务门户，不进入管理台模块 |

角色边界详见 [角色矩阵.md](./角色矩阵.md)。直接输入不可见模块 URL 时，路由守卫会按同一角色矩阵拦截。

## 4. 第一次使用：核心验收流程

```bash
# 1. 启动三端
./manage.sh start

# 2. 烟测
bash scripts/smoke-test.sh

# 3. 浏览器访问
open http://localhost:5173
```

基础环境清单：

- [ ] `/`、`/portal` 可打开，无白屏
- [ ] 登录成功（默认账号见 `application-dev.properties` 或种子脚本）
- [ ] `/dashboard/agents/manage` 可打开，智能体管理入口可见
- [ ] 知识库管理和知识检索入口可打开
- [ ] `/dashboard/system/security-ops` 可打开，统一网关与审计入口可见

产品闭环清单：

- [x] 接入一个真实可用的模型 Provider（手工 / 既有 onboard）
- [x] 创建知识库并上传一份最小文档（`ORIN_BUSINESS_SMOKE_KNOWLEDGE_GOLDEN=1` 或管理台）
- [x] 文档完成解析和向量化，检索测试返回相关片段
- [x] 创建智能体并绑定该知识库（agent `kbIds` 绑定；工作台同步）
- [x] 智能体回答包含可核对的知识依据或引用（workspace session + citation chips）
- [x] 能从失败回答跳转或检索到 traceId、错误信息和审计记录（响应字段 + Trace summary）
- [x] 通过 API Key 完成一次发布后调用（发布 = `mcpExposed` + `/v1/mcp`）

自动化入口：

```bash
ORIN_BUSINESS_SMOKE_KNOWLEDGE_GOLDEN=1 \
ORIN_BUSINESS_SMOKE_AGENT_ID=<agentId> \
bash scripts/business-smoke.sh
```

## 5. 联调要点

### 5.1 看接口是否真存在

```bash
# 直接搜后端控制器
rg "@RequestMapping|@GetMapping|@PostMapping" \
   orin-backend/src/main/java/com/adlin/orin

# 或打开 Swagger
open http://localhost:8080/swagger-ui/index.html
```

### 5.2 看页面入口是否还在用

```bash
# 路由常量
sed -n '1,260p' orin-frontend/src/router/routes.js

# 顶部菜单可见性（角色过滤与开关）
sed -n '1,260p' orin-frontend/src/router/topMenuConfig.js

# 找开发中提示或未启用提示
rg "开发中|未启用|待实现" orin-frontend/src
```

### 5.3 看工作流/协作是否真执行

涉及工作流、协作、知识链路时，必须同时核对三层：

1. 前端节点配置和入口页
2. Java 后端控制器与代理层
3. Python `orin-ai-engine/app/engine` 节点处理器与 TaskRuntime

页面可点开 ≠ 能力闭环。

## 6. 文档使用原则

- 路由常量、菜单项、组件文件三者都存在，仍不等于能力闭环
- 部分路径（版本管理、协作配置等）是同页面别名复用
- 模块成熟度请对照 [功能完成度.md](./功能完成度.md)
- 接口字段以 Swagger 与控制器代码为准

## 7. 历史路径与重定向

以下路径来自 `LEGACY_ROUTE_REDIRECTS` 或旧文档，仅用于兼容访问和排查历史链接，不作为当前主导航入口：

| 旧路径示例 | 当前处理口径 |
|------------|--------------|
| `/dashboard/agents/list`、`/dashboard/agents/onboard`、`/dashboard/agents/chat-logs` | 重定向到智能体相关落地页，主入口从 `/dashboard/agents/manage` 或 `/dashboard/agents/session` 进入 |
| `/dashboard/applications/*` | 多数是当前落地页常量或旧别名；菜单入口以本指南第 2 节和 `topMenuConfig.js` 为准 |
| `/dashboard/knowledge/*` | 历史知识库路径；从“知识库”入口进入 |
| `/dashboard/resources/*` | 知识资源落地页常量；不作为二级分组主入口 |
| `/dashboard/runtime/*` | 运行监控落地页常量；管理员从“运行监控”进入 |
| `/dashboard/control/*` | 组织权限与系统设置的落地页常量 |
| `/dashboard/system/users`、`/dashboard/system/api-keys`、`/dashboard/system/audit-logs` | 旧系统管理路径；通过当前组织权限、系统设置或门户入口访问对应能力 |
