# F01 · 接入并监控服务器

> 状态：E2E Working
> 最后更新：2026-07-27
> 用户角色：Operator / Administrator
> 前置功能：无
> 关联决策：[ADR-001](../adr/001-runner-dispatch-and-lease.md)

## 1. 用户问题与结果

用户拥有一台可以运行 Agent 的服务器，但当前 ORIN 没有安全、轻量的接入方式，也无法在产品中确认机器是否在线、是否有容量或为什么不可用。

完成后，用户可以从 Workspace 生成一次性接入命令，在自己的服务器启动 Runner，并在同一页面看到真实在线状态、资源、版本和最近心跳；用户还可以安全地 Drain、恢复或 Revoke 这台 Runner。

## 2. 范围

### 2.1 本功能包含

- Workspace 的 Runner 列表、接入向导和详情；
- 一次性 Enrollment Token 与独立 Runner Credential；
- Runner 主动出站 enrollment、heartbeat、重连和安全退出；
- CPU、内存、磁盘、GPU（存在时）、并发容量、版本、标签与依赖健康；
- `NEW / ENROLLING / ONLINE / DEGRADED / DRAINING / OFFLINE / REVOKED` 状态；
- Drain、恢复、Revoke 及对应审计；
- Docker 与 systemd 至少一种可真实执行的安装方式，另一种可随后补齐到 Production Ready。

### 2.2 本功能不包含

- AgentVersion、Run lease 和任务执行；
- 自动扩缩、云主机创建或 Kubernetes 式调度；
- 通用服务器监控、远程 Shell、Docker Socket 或文件浏览；
- 把旧 Server Monitor 页面换皮后直接复用。

## 3. 完整用户旅程

1. Operator 打开 `/workspace/runners`，看到真实 Runner 列表或说明下一步的空状态；
2. 点击“接入服务器”，选择安装方式并生成短期、一次性的 Enrollment Token；
3. 页面显示可复制命令，并明确过期时间、目标 Control Plane 地址和安全提醒；
4. 用户在另一台服务器执行命令，Runner 主动出站注册并换取独立 Credential；
5. 页面在目标时间内从 ENROLLING 更新为 ONLINE，显示真实资源、版本和最近心跳；
6. 用户停止 Runner 后，页面在超时窗口内显示 OFFLINE 和原因；重启后使用既有有效 Credential 恢复 ONLINE；
7. 用户执行 Drain 后，页面显示 DRAINING；恢复后回到 ONLINE；
8. 用户执行 Revoke 并确认风险，页面显示 REVOKED，旧 Credential 后续请求被拒绝且写入审计。

## 4. 产品与系统协作

### 4.1 前端

- Runner 列表以状态、名称、Pool/标签、资源摘要、最近心跳为核心，不做通用监控大盘；
- 接入向导展示一次性命令、复制反馈、过期倒计时和常见失败排查；
- Runner 详情展示与 Agent 运行相关的资源、依赖健康和状态变化；
- Drain、恢复和 Revoke 必须有权限校验、确认和明确反馈；
- 加载、空状态、无权限、Enrollment 过期、离线、降级和撤销状态均可见。

### 4.2 Java Control Plane

- 作为 Runner、Enrollment Token、Credential、HeartbeatSnapshot 和审计的唯一持久化方；
- Enrollment Token 短期、一次性、使用后不可重放；
- Runner Credential 与用户 JWT、Endpoint API Key 类型和鉴权链隔离；
- 心跳接收、状态推导、超时扫描、Drain/恢复/Revoke 使用一致状态机；
- 所有敏感写操作记录 actor、runnerId、结果与 traceId，不记录 token 明文。

### 4.3 Runner

- 主动出站连接 Control Plane，不要求服务器开放公网入站端口；
- Credential 只写入权限受限的本地配置，不打印到日志；
- 上报允许的资源和依赖健康，不上报 Secret、进程数据、Run 输入输出；
- 网络中断使用有上限退避重连；收到 401/403 后按协议停止；
- 不连接 ORIN 业务数据库，不消费 RabbitMQ，不执行任务。

### 4.4 数据、权限与审计

- Creator 默认只读可用 Runner；Operator 管理接入与 Drain；Administrator 可 Revoke；最终权限以[角色矩阵](../角色矩阵.md)为准；
- Enrollment 创建/消费/过期、Credential 签发/撤销、Drain/恢复、状态异常均可审计；
- UI 不回显 Enrollment Token 或 Runner Credential 的历史明文。

## 5. 验收

### 5.1 正常路径

- [x] 从全新服务器复制页面命令即可启动 Runner，无需手工写数据库；
- [x] Runner 在约定时间内显示 ONLINE，并展示真实 CPU、内存、磁盘、容量、版本与最近心跳；
- [x] 停止后在超时窗口内显示 OFFLINE，重启后恢复；
- [x] Drain、恢复、Revoke 从 UI 到 Runner 行为闭环；
- [x] Runner 不开放入站端口、不连接业务数据库。

### 5.2 失败与恢复

- [ ] Token 过期、重复消费、Control Plane 地址错误和网络中断有明确错误与排查建议；
- [ ] Credential 无效返回 401，身份已撤销返回 403，Runner 停止后续请求；
- [ ] DEGRADED/OFFLINE/REVOKED 原因可见，页面不展示伪造资源；
- [ ] 心跳重复、乱序或短暂网络抖动不会创建重复 Runner。

### 5.3 自动化与手工证据

- [x] 后端状态机、原子 Enrollment、Credential、Heartbeat、机器鉴权和审计测试；
- [x] Runner enrollment、Drain 期间持续心跳、重连、401/403 和安全存储测试；
- [x] 前端浏览器 mock 集成：生成命令 → Drain → Restore → Workspace 详情监控 → Revoke；
- [x] 真实后端浏览器 E2E：生成命令 → 启动 Runner → ONLINE → Drain → Restore → 停止 → OFFLINE → Resume → Revoke；
- [x] 隔离 Docker Runner 生命周期 smoke：`scripts/f01-runner-lifecycle-e2e.sh` 于 2026-07-26 通过（Enrollment → ONLINE → Drain ACK → Restore → OFFLINE → Resume → Revoke/退出）。

### 5.4 当前实现证据（2026-07-27）

- Java Control Plane、Python Runner 与 `/workspace/runners` 的列表和详情入口已经接通；旧 `/dashboard/runtime/server` 仅保留为兼容入口；
- Enrollment 在同一数据库事务内锁定并消费 Token、创建 `ENROLLING` Runner、签发 Credential；首次真实心跳才切换 `ONLINE`；
- Drain 不终止机器通道，Runner 只确认一次命令并继续心跳；离线扫描保留 Drain 意图，Restore 不会伪造离线 Runner 已上线；
- `scripts/f01-runner-lifecycle-e2e.sh` 已在本机真实 Control Plane + Docker Runner 上通过，覆盖 Enrollment → ONLINE → Drain ACK → Restore → OFFLINE → Resume → Revoke/Runner 退出；它使用带时间戳的 Docker 容器、volume 和临时目录，并在退出时仅清理这些资源；
- 前端严格 lint、154 个单测和 production build 已通过；F01 Playwright mock 主路径覆盖 Workspace 路由；
- `tests/e2e/real-backend/runner-f01-real.spec.js` 于 2026-07-27 通过：由 Workspace 生成一次性命令、Docker Runner 主动出站 enrollment、ONLINE、详情页 Drain/Restore、OFFLINE、resume 与 Revoke/进程退出均经真实 Control Plane 验证；
- 因此状态升级为 `E2E Working`。systemd 安装、独立物理机与生产运维验收仍属于 `Production Ready` 后续工作，不以本状态冒充完成。

## 6. 不算完成

- 只有 Runner Entity、迁移、Controller 或 Swagger；
- 只有 Runner 模拟器，没有真实进程；
- 只有 curl，没有 Workspace 接入入口；
- 页面使用假心跳或随机资源；
- 未验证 OFFLINE、Drain、Revoke 和 Credential 失效；
- 安装命令仍是不可执行占位符。
